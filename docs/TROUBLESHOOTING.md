# SENTINEL 2.0 - Comprehensive Troubleshooting Matrix

This guide provides symptoms, probable causes, diagnostic steps, and immediate corrective actions for all hardware, firmware, network, and AI subsystems.

| # | Symptom | Probable Cause | Diagnostic Step | Corrective Action |
|---|---|---|---|---|
| 1 | **ESP32 not detected on USB** | Missing CP2102/CH340 driver or charge-only USB cable | Check Device Manager (Windows) or `ls /dev/tty*` (Linux/Mac) | Install CH340 or CP210x VCP driver; replace USB cable with high-quality data cable. |
| 2 | **Compilation error: `Adafruit_SSD1306.h not found`** | Library not installed in Arduino IDE | Check Library Manager in IDE | In Arduino IDE: Tools -> Manage Libraries -> Install `Adafruit SSD1306` & `Adafruit GFX`. In PlatformIO: verify `platformio.ini` lib_deps. |
| 3 | **OLED screen completely blank** | Swapped I2C pins, wrong I2C address, or missing power | Run I2C Scanner sketch in Serial Monitor | Ensure `SDA` is on `GPIO 21`, `SCL` is on `GPIO 22`. Verify module address: change `#define OLED_I2C_ADDR 0x3C` to `0x3D` if scanned at 0x3D. |
| 4 | **ADC reading always 0 or 4095** | Sensor connected to wrong pin, sensor unpowered, or floating pin | Probe sensor VCC and Signal with multimeter | Verify sensor is plugged into `3V3` and `GND`. Check that pulse sensor is on `GPIO 34` and GSR on `GPIO 35`. |
| 5 | **ADC reading freezes when Wi-Fi connects** | Sensor plugged into an ADC2 pin on classic ESP32 | Check pin definition in `config.h` | **Move sensor to ADC1 pins** (`GPIO 32, 33, 34, 35, 36, 39`). Classic ESP32 disables ADC2 during Wi-Fi transmission! |
| 6 | **Noisy pulse signal / irregular spikes** | Excessive ambient light or finger pressed too hard against sensor | Open Arduino Serial Plotter at 115200 baud | Shield the sensor from bright ambient lights with a small piece of dark tape. Rest finger lightly on sensor without pressing tightly. |
| 7 | **BPM repeatedly jumps between wild values** | Counting electrical noise or dicrotic notch | Check `consecutiveValidBeats` counter | Increase `PULSE_REFRACTORY_MS` from 300 to 340ms; ensure `PULSE_REQUIRED_CONSECUTIVE` is >= 4. |
| 8 | **GSR reading stays dead flat** | Electrodes not contacting skin, dry skin, or open circuit | Measure resistance between finger straps with multimeter | Ensure straps are snug on palmar side of fingers; moisten fingertip slightly if skin is extremely dry. |
| 9 | **Wi-Fi refuses to connect to home router** | ESP32 only supports 2.4 GHz Wi-Fi (not 5.0 GHz) or typo in SSID | Check Serial Monitor output | Connect to your router's 2.4 GHz band, or use ESP32 built-in SoftAP mode (`SENTINEL-2-AP`). |
| 9a | **ESP32 repeatedly drops from Wi-Fi** | Weak 2.4 GHz coverage, router band steering, power-save latency, or repeated reconnect attempts | Keep the ESP32 near the router and observe `[WIFI]` messages in the Serial Monitor | Disable band steering or use the dedicated 2.4 GHz SSID. Keep the firmware's `SENTINEL-2-AP` fallback available and connect the dashboard to `192.168.4.1`; the firmware disables Wi-Fi sleep and backs off station retries. |
| 10 | **Browser cannot reach ESP32 IP** | Laptop and ESP32 on different networks or AP isolation enabled | Run `ping <esp32-ip>` in laptop terminal | Connect laptop Wi-Fi to same network or directly connect to `SENTINEL-2-AP`. |
| 10a | **Dashboard says the ESP32 request timed out** | Stale IP or the laptop and ESP32 are on different networks | Check the current IP on the OLED. If it is `192.168.4.1`, the ESP32 is in SoftAP mode | Join the laptop to `SENTINEL-2-AP`, select **Use AP IP** in the dashboard, and keep the dashboard open at `localhost`. SoftAP has no internet; the browser's offline indicator is expected. Otherwise use the current OLED IP with both devices on the same router Wi-Fi. |
| 11 | **CORS error in browser console** | Cross-origin headers missing on ESP32 | Inspect browser console network tab | Ensure `server.enableCORS(true)` is present in `sentinel.ino`. |
| 12 | **Backend fails to start (`EADDRINUSE: 3000`)** | Another process is holding port 3000 | Check terminal output on `npm run dev` | Run `fuser -k 3000/tcp` (Linux) or change port to `PORT=3001` in `.env`. |
| 13 | **Groq authentication error (401 Unauthorized)** | Invalid or expired Groq API key | Check `.env` file | Obtain new key from `console.groq.com` and set `GROQ_API_KEY="gsk_..."`. |
| 14 | **Groq model unavailable (404 Not Found)** | Model deprecated or misspelled | Check server logs | Set `GROQ_MODEL="llama-3.3-70b-versatile"` or `GROQ_MODEL="llama-3.1-8b-instant"` in `.env`. |
| 15 | **Groq rate limit reached (429 Too Many Requests)** | Too many rapid requests sent to Groq | Check HTTP status code | SENTINEL automatically throttles requests and falls back to Google GenAI or local rule engine. |
| 16 | **AI Interpretation button disabled** | Session too short (<10s), no mean BPM, or too few valid pulse samples | Check the completed session summary for valid BPM samples | Stop a session of at least 10 seconds with valid pulse data. GSR may be unavailable; the AI button is gated by pulse data, not GSR calibration. |
| 17 | **Charts appear blank or flatline** | Telemetry stream paused or sensor disconnected | Check "Device Status" indicator in header | Ensure device is connected or switch to "Hardware Simulator" mode to test graphs. |
| 17a | **Heart rate stays on SEARCHING / WEAK PPG SIGNAL** | Pulse ADC excursions are too small/noisy, sensor polarity differs, or finger contact is poor; an earlier timeout/rejected beat may also have left stale timing state | Check if GPIO 34 raw ADC changes with a light, steady finger; inspect the pulse waveform and its min/max values | The processor now re-anchors after rejected beat intervals and clears stale beat timing after signal loss, so it can reacquire instead of remaining stuck. Keep the finger still, shade the sensor, verify GPIO 34/3.3 V/GND, and allow 4 regular beats. If the trace stays flat, check the sensor/module and wiring; software cannot recover a pulse that is not present in the ADC signal. |
| 18 | **Timestamps jumping backwards** | Clock mismatch or out-of-order packets | Inspect sequence number | `ProtocolValidator` automatically filters out-of-order packets. Check ESP32 uptime. |
| 19 | **OLED flickering rapidly** | Calling `display.display()` on every 100Hz loop iteration | Inspect `loop()` in sketch | OLED update is throttled to 10 FPS (100ms) in `sentinel.ino`. |

### Requesting the AI response

In the dashboard's **Telemetry** tab, start a session, collect at least 10 seconds of usable readings, and stop the session. The **Groq AI Physiological Response Assistant** panel below the charts summarizes that completed session. Select **Request AI Interpretation** to display the observation and suggestion in the panel. If the button stays disabled, check the session's pulse quality and valid-beat ratio. No response is generated automatically.
